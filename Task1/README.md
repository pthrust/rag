# Аналитический отчёт: выбор инструментов для RAG-бота QuantumForge Software

# 1. Сравнение LLM-моделей

## 1.1 Облачные модели (OpenAI, YandexGPT)

| Критерий | OpenAI (GPT-4o-mini) | YandexGPT 5.1 Pro |
| :--- | :--- | :--- |
| **Качество ответов** | Очень высокое | Высокое, хорошая работа с русскоязычными запросами |
| **Скорость** | Низкая латентность, API-вызовы ~100-300 мс | Сопоставима с OpenAI |
| **Стоимость** | $0.15/вход, $0.60/выход за 1M токенов | ~0,40 руб./1000 токенов (~$0.004/1K) |
| **Развёртывание** | Мгновенное, через API | Мгновенное, через API, совместимость с OpenAI API |

## 1.2 Локальные модели (Hugging Face)

| Критерий | Оценка |
| :--- | :--- |
| **Качество** | Зависит от модели: Llama 3.1 8B, DeepSeek-R1 14B показывают хорошие результаты, но уступают топ-облачным |
| **Скорость** | Зависит от железа: на GPU ~10-20 сек/запрос, на CPU значительно медленнее |
| **Стоимость** | $0.001–0.04 за 1M токенов (только электроэнергия) — в 40–200 раз дешевле облачных API |
| **Развёртывание** | Требует настройки инфраструктуры, GPU-инстансов, управления моделями |

> **Вывод:** Для **QuantumForge Software**, где важна конфиденциальность данных и регуляторные требования, локальные модели предпочтительнее с точки зрения безопасности. Однако **YandexGPT 5.1 Pro** предлагает хороший баланс: высокое качество, низкая стоимость (0,40 руб./1000 токенов) и совместимость с OpenAI API, что упрощает интеграцию с *LangChain*.

# 2. Сравнение моделей эмбеддингов

| Критерий | Sentence-Transformers (локальные) | OpenAI Embeddings (облачные) |
| :--- | :--- | :--- |
| **Модель** | all-MiniLM-L6-v2 (384 dim) | text-embedding-3-small (1536 dim) |
| **Скорость индексации** | ~200-500 мс на CPU | Batch-режим: до 2048 входов за вызов |
| **Качество поиска** | MTEB 62.3 | MTEB 62.3 |
| **Стоимость** | Бесплатно (локальный запуск) | $0.02 за 1M токенов |
| **Память** | ~200 MB VRAM | Не требуется (облачные вычисления) |
| **Multilingual** | all-MiniLM-L6-v2 теряет >20% точности на не-английском | Поддерживается |

> **Вывод:** Для **MVP** и прототипирования **Sentence-Transformers (all-MiniLM-L6-v2)** — оптимальный выбор: нулевая стоимость, простота развёртывания, достаточное качество. Для продакшена с мультиязычной документацией лучше рассмотреть multilingual-модели или **OpenAI Embeddings**.

# 3. Сравнение векторных баз данных: ChromaDB vs FAISS

| Критерий | FAISS | ChromaDB |
| :--- | :--- | :--- |
| **Скорость поиска** | 0.19 мс на запрос | 0.76 мс на запрос |
| **Скорость индексации** | 0.024 с для 20K векторов | 2.806 с для 20K векторов |
| **Точность (Recall@5)** | 1.00 (эталон) | 0.002 (значительное падение при HNSW) |
| **Масштабируемость** | Доказана до 2.2M чанков | Проблемы на масштабе >10K чанков |
| **Сложность внедрения** | Низкая (библиотека, in-memory) | Низкая (embedded DB) |
| **Персистентность** | Нет (in-memory, требуется ручное сохранение) | Есть (встроенное хранение на диске) |
| **Стоимость** | Бесплатно (open-source) | Бесплатно (open-source) |

> 📌 **Ключевое наблюдение:** В исследовании на *2.2M чанков* **FAISS** показал коэффициент вариации (CV) **2.5%** против **8%** у **Chroma** — то есть FAISS даёт более стабильные и предсказуемые результаты.

**Вывод:**

* **FAISS** — выбор для продакшена: максимальная скорость, точность и масштабируемость. Идеален для **18 000+ Markdown-файлов** в репозиториях и **3 000 страниц Confluence**.
* **ChromaDB** — выбор для быстрого прототипирования и разработки, но не для масштаба *QuantumForge*.

# 4. Рекомендуемая конфигурация сервера

Для развёртывания RAG-бота с локальной LLM (**8B параметров**) и **FAISS**:

| Компонент | Минимальная конфигурация | Рекомендуемая (Production) |
| :--- | :--- | :--- |
| **CPU** | 8 ядер | 16+ ядер (Intel Xeon) |
| **RAM** | 32 GB | 64–128 GB |
| **GPU** | RTX 4060 Ti 16GB | RTX 3090 24GB или A10G |
| **Storage** | 500 GB NVMe SSD | 2 TB NVMe SSD |
| **Ориентировочная стоимость** | ~$400 | $2,500–3,800 |

## Итоговые рекомендации

### Вариант 1: MVP / Prototype
* **LLM:** YandexGPT 5.1 Pro (API, ~0,40 руб./1000 токенов)
* **Embeddings:** Sentence-Transformers `all-MiniLM-L6-v2` (локально, бесплатно)
* **Vector DB:** FAISS (in-memory, максимальная скорость)
* **Infra:** CPU-сервер **8 ядер / 32 GB RAM**
* **Плюсы:** Минимальные затраты на разработку, быстрое развёртывание.
* **Минусы:** Зависимость от облачного API для LLM.

### Вариант 2: Production
* **LLM:** Локальная (Llama 3.1 8B / DeepSeek-R1 14B) — контроль данных и **SOC 2 compliance**.
* **Embeddings:** `BAAI/bge-large-en-v1.5` (1024 dim) — лучшее качество среди open-source.
* **Vector DB:** FAISS — максимальная скорость, точность и масштабируемость.
* **Infra:** GPU-сервер (**RTX 3090 24GB**) + **64 GB RAM**.
* **Плюсы:** Полный контроль данных, отсутствие per-token затрат, масштабируемость до 2M+ чанков.
* **Минусы:** Начальные капитальные затраты на железо (**~$3,000**).

### Вариант 3: Гибридный (баланс)
* **LLM:** YandexGPT 5.1 Pro (API) для генерации ответов.
* **Embeddings:** Локальные Sentence-Transformers.
* **Vector DB:** FAISS.
* **Infra:** CPU-сервер + API-доступ к YandexGPT.
* **Плюсы:** Баланс между контролем данных и стоимостью.

### Вариант 4: Полностью облачный
* **Концепция:** Всё на OpenAI / Yandex Cloud.
* **Плюсы:** Нулевое управление инфраструктурой.
* **Минусы:** Высокие операционные затраты, риски безопасности, невозможность пройти **SOC 2** с конфиденциальными данными клиентов.
